# 4. 段落插在列表项之后，不是列表项里面

日期：2026-10-13
状态：已采纳
影响版本：afk-bootstrap 1.7.20（`upgrade-afk.sh` 的 `1.7.19 -> 1.7.20` 步骤）

## 背景

1.7.19 把这条纪律铺到了 5 条 promptFile 上。插入点是 `anchor + 1`，**无条件**。
`.sandcastle/implement-pr/prompt.md` 的锚点是编号列表的**第 3 项**，而第 3 项的文字
在下面四行缩进续写。于是段落落在了**项与它自己的续行之间**：

```
3. Make the code changes you decided on. …

Before you settle on an approach, search…
yourself — do not spend a human's time on them.
   If the repo has a project verification skill …
   cannot run it, say so … in the commit body; do not report it as done.
4. If you made no changes that's fine …
```

那个缩进块是第 3 项的**验证指令**，被一句话从它所属的步骤里隔开了。health-flow 上
实测复现，Devin Review 在该 PR 上报了同一条。

四仓里只有 health-flow 的这条 prompt 带续行（另外三仓该行被改写过），但**四仓都带着
错位的段落** —— 1.7.19 一发布就落地了。

## 决定

**插入点是「锚点所在那一项的末尾」，不是「锚点行的下一行」。** 列表项由
`^\s*(?:\d+[.)]|[-*+])\s` 认出，续行是「有前导空白且本身不是新项」的行。

工具改成**幂等且会纠位**：找出本模板写过的那段逐字文本的所有副本，删掉多余的，
把一个放到正确的行之后。**项目自己改过措辞的那份一个字节都不碰** —— 它匹配不上，
工具就不认它是自己的。

副本的位置用**原始行号**在一次遍历里落位，不在过滤后的数组上重新找锚点：后者是
上一版的 bug，`insertionPoint` 在移位后的列表上返回 -1，于是文件被写成「所有副本
都删掉、一个也没放回」。四仓的 `implement-prd/prompt.md` 都复现过，smoke 抓到了。

## 被否掉的方案

- **把修复并进 1.7.19 那一步。** 现场的项目**已经跑过那一步**，并带着错位的段落；
  修复折进肇事的那一步，就永远到不了它们手里。必须是新版本。

- **只修 health-flow（唯一带续行的那个）。** 错位在四仓都存在，只是另外三仓的
  续行被改写过，症状暂时看不出来。按症状修一处，就是把同一个缺陷留在另外三处。

- **按「段落后面是不是缩进行」来判断要不要搬。** 那是从**症状**反推，续行本身
  可能也被改写。判据是**锚点是不是列表项**——它是原因，且不依赖续行长什么样。

## 后果

- **fixture 的来源要按文件真实来源取。** `implement-prd/prompt.md` 由
  `bootstrap-afk.sh:130` 从 `templates/prompt.<lang>.md` 渲染，**不是** scaffold 里那份；
  scaffold 的那份**根本没有 `policy-check.mjs commit` 锚点**。用错来源的 fixture 会去
  测「没有锚点」这条路径，而真实仓库走的是另一条。smoke 已按各自来源取文件，并把
  这个理由写在 `SOURCE` 表上。

## Devin Review 的第三轮：三个会丢数据的分支

四条里三条经复现成立，都是同一类——**工具在放不下段落时把已有的段落删了**：

| # | 症状 | 复现 |
| --- | --- | --- |
| 1 | 锚点被项目改写时，段落被删掉、rc=3、升级继续并盖上 1.7.20 | 段落 1 → 0 |
| 2 | 段落与后面的编号步骤之间没有空行，`4.` 被吞进段落、不再是列表项 | 渲染成正文 |
| 3 | 锚点在末行且无尾换行时，删掉旧段落、一个也没放回，却报成功 | 段落 1 → 0 |

（第 4 条是"重跑幂等没有测试"，已补断言。）

**共同点：删除与插入是两段独立代码，只有插入那半被测试覆盖。** 修法是让「删除 + 放回」
成为**一个**函数 `spliceParagraph(arr, at)`，两条调用路径都必须经过它——空行在前后
两侧都由它算，所以两个分支不可能对间距有不同意见。锚点找不到时**直接 `exit 3`、一个
字节都不写**：「放不下」不是「可以删」的理由。

## 验证

`test/smoke.sh` 新增 1.7.20 段：fixture 造出 1.7.19 的错位形态（段落夹在项与续行之间），
升级后断言四者顺序为 `3.` < 续行 < 段落 < `4.`。

两条负向对照真跑过：

| 注入 | 结果 |
| --- | --- |
| 1.7.20 门控改成 `-lt 0`（等于该步不存在） | `order is item@1655 continuation@2163 duty@1887 next@2629` |
| `continues()` 恒为 false（不再识别续行） | 同上 |

以及幂等：重跑一次 rc=4，5 条 prompt 仍各有且仅有一份。
