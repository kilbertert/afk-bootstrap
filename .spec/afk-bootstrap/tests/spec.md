# tests

装配器自己的验证。它比多数项目更吃重，因为**装配器的缺陷会复制到每个被装配的仓库**。

## raw source

反复出现的失败形态只有一个：**夹具与真实形状不一致**，于是断言在一个从未存在过的树上通过。

已量出的三处：

- fixture 用 `git show HEAD:<file>` 取"改动前"的形状——CI 检出的是 PR 的**合并提交**，
  里面已含这次改动，剥不到东西。**本机绿、CI 红**；更坏的是它可能一个断言都不碰就通过。
  做法：改动前的形状进 `references/`，并**在 fixture 里断言那份 reference 确实不含新东西**。
- 判据串跨行（`src.includes(...)`）而插入是按行做的——跨行短语**永远匹配不上**，
  于是 `exit 4` 从不触发、每次升级再插一份。
- 手敲夹具的缩进 → 造出"从未发布过的形状"，断言什么都不证明。
  **从脚手架的原始字节里按标记整行删除**来构造上一版形态。

## 不变量

- 夹具的"改动前"形状来自 `references/`，**不来自 HEAD**。
- 判据落在**解析结果**上（YAML 用解析器），动作落在**那一步自己的行范围**上，
  改完**再解析一次断言结果**——"编辑没发生却打印成功"是本仓库出现过的失败。
- CI 的 shellcheck 用**默认严重度**（info 级也失败）；本地复验不加 `-S`。
