# 13. 一圈用几核 —— 并行的上限是「跑多宽」，事故来自「同时几次」

日期：2026-10-23
状态：Accepted
影响版本：`templates/implement.python.md`（`-n auto` → `-n 4`）；
`scaffold/.sandcastle/sandbox-prepare.sh`（指引里的拼写）；
`upgrade-afk.sh`（1.7.29 步骤；1.7.28 步的 lookahead 收窄到「任何 `-n`」；
1.7.27 步的归一化加第三种拼写）；`test/smoke.sh`（1.7.28 断言改 `-n 4` + 新增 1.7.29 段）

## 背景

ADR 0012 让每圈检查跑并行，实测 249.7 s → 46.4 s。它写下的代价是：

> `-n auto` 在 8 核沙箱里会与其他进程争抢……争抢只会让它退化到 `-n 4` 附近的量级，
> 不会比串行更差。

那句话在一个方向上是对的——**单次跑**在争抢下确实不会比串行差。它漏掉的是另一个轴：
**同时存在几次跑**。`auto` 是 `os.cpu_count()`，所以 N 个并发不是「退化到 `-n 4`」，
而是 **N × 8 个 worker**。

2026-10-23 实测到了这个漏掉的那一轴：多台 agent 会话在同一台宿主上同时跑全套，
load average 从 5.28 顶到 **79**；`sshd` 和 `tailscaled` 抢不到 CPU，tailnet 掉线，
**管理这台机器的通道本身消失了**。不是「变慢」，是不可达。

沙箱不是容器：AFK 的 agent 在 `runs-on: self-hosted` 上跑，与 python、编辑器、
其他会话共享同一组核。所以「沙箱里只有我一个」这个前提在这里不成立。

## 决定

**两处一起改，因为它们限制的是两个不同的东西，只改一个事故就会回来。**

1. **`-n auto` → `-n 4`**（模板 + 升级步骤）。限制「一次跑多宽」。
   8 核的一半，对 4 核的 GitHub-hosted runner 也正合适；比串行仍快 3.4 倍
   （ADR 0012 已测 72.5 s）。

2. **并发次数由消费仓自己的 `tests/conftest.py` 网关限制**，AFK 侧**做不到**，
   所以升级步骤 `note` 出来而不是假装做了。AI-Ops 的实现是
   `MAX_CONCURRENT_RUNS=2` 的主机级槽位 + checkout 锁（见该仓 PR）。

## 被否的方案

- **只改模板数字，不动升级步骤。** 这正是 ADR 0003 反复出现的缺陷：规则下发到
  作者想到的那条路径（新项目），不到每一条会加载它的路径（老项目）。
  1.7.28 自己也犯过一次，本仓 #107 就是修它。

- **保持 `-n auto`，只靠 conftest 锁。** 锁限制并发次数，但一次 `-n auto` 仍然
  吃满全机。两个限制是正交的，缺一个就留一半的洞。

- **把上限做成 AFK 的一个环境变量**（如 `PYTEST_ADDOPTS=-n 4`）。实测过：
  `addopts`/`PYTEST_ADDOPTS` 无条件生效，在没装 xdist 的机器上直接
  `unrecognized arguments: -n`，**一个测试都不跑**。这条在 AI-Ops 已记录过两次。

## 后果

- 每圈从 46.4 s 变为 72.5 s（同 ADR 0012 的 `-n 4` 实测），仍比串行快 3.4 倍。
  多出来的 26 s 买的是「宿主的 sshd 还能被调度到」。
- **升级要认三种命令拼写**：`uv run pytest`（无参数）、`-n auto`（1.7.28）、
  `-n 4`（1.7.29）。1.7.27 步的归一化从两种扩到三种——否则一次 1.7.28 → 1.7.29
  的升级会让它把 `-n 4` 读成「项目手改过」，静默拒绝下发判据。
  ADR 0012 的「一处跨版本失效」是同一个形状，这是它第二次发生。
- **1.7.28 步的 lookahead 从 `(?! -n auto)` 收窄到 `(?! -n )`**。实测：
  消费仓若是 `-n 4`，它匹配 `uv run pytest` 后再补一个，得到
  `uv run pytest -n 4 -n 4`。pytest **接受重复的 `-n` 并正常跑**，所以没有任何东西变红。
  脚本按版本幂等，重复执行是正常路径而不是边角情况。
- **`implement-prd/prompt.md` 的命令是分段写的**（`` `uv sync --extra dev`, `uv run pytest`, ``），
  不含 `-n`，1.7.29 的替换在它身上**不触发**，这是对的：给一个项目没写过 worker 数的
  命令凭空加一个，是这个步骤在改它没被要求改的东西。smoke 里有一条正向断言钉住它。

## 仍未做

- 并发次数的闸门没有被 AFK 下发。它必须活在消费仓的 `conftest.py` 里
  （每个仓库的 fixture 与端口占用不同），本仓无法写。升级输出会点名这条缺口。
