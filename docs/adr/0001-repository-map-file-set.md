# 1. 仓库地图的文件集取自 git，不取自文件系统

日期：2026-10-08
状态：已采纳
影响版本：afk-bootstrap 1.6.4（`upgrade-afk.sh` 的 `1.6.3 -> 1.6.4` 步骤）

## 背景

`.sandcastle/REPO-MAP.md` 是 AFK 实现提示让 agent **第一个读**的文件：它回答"东西在哪"，
用来替掉那次实测中 62 次工具调用里的 36 次 `cat`/`ls`/`grep`。它的内容是机械的 —— 只报
文件系统与 manifest 已经说了什么，不猜架构。

它由 `repo-map.mjs` 从**文件系统遍历**生成，并由 `repo-map.check.mjs` 在 CI 的策略任务里
比对新鲜度（重新生成、与提交的比对、不一致即红）。

四个消费仓库升到 1.6.3 后的收尾验证里出现了一个现象：

| | 本机 `repo-map.check.mjs` | CI 策略任务 |
| --- | --- | --- |
| health-flow | 红 | 绿 |
| genesis-evidence | 红 | 绿 |
| AI-Ops | 红 | 绿 |
| Auto-Test | 红 | 绿 |

同一个提交，两边给相反答案。

## 决定

**地图的文件集定义为 git 的视图：**

```
git ls-files --cached --others --exclude-standard
```

即 **已跟踪文件 + 未跟踪但未被忽略的文件**。被 `.gitignore` 命名的路径一律不在集合内。

判定时用这个集合过滤目录遍历：一个目录只有在其中存在集合内路径时才下降，一个文件只有在
集合内时才进入地图。`entryPoints` / `testLayout` / `docs` 的存在性判断、以及 `docs/` 的
markdown 计数，全部改走同一个集合。

`SKIP` 集合保留，但职责收窄为一个：**限定遍历范围**，防止一个未被忽略的 `node_modules/`
在新鲜克隆里拖进成千上万行。

### 为什么选这个集合，而不是"仅已跟踪"

两处调用点在**提交之前**生成地图，那时脚手架刚写的文件还没被 `git add`：

- `bootstrap-afk.sh` —— 生成地图在脚手架写入之后、提交之前；
- `upgrade-afk.sh` —— 生成地图在发布阶段，同样早于操作员的提交。

"仅已跟踪"会让这两处生成一张几乎空白的地图。而"未跟踪但未被忽略"恰好就是脚手架刚写的
那些文件：它们没有被 ignore（脚手架会把自己的 `node_modules/` 写进 `.gitignore`），所以
在集合里。

## 理由

1. **git 视图由仓库定义，不由磁盘定义。** 同一份 `.gitignore` 在本机与 CI 都生效，所以两边
   的文件集相同；文件系统遍历在本机看到 `artifacts/`、`local DB`、`.venv` 作用域等构建残渣，
   而 CI 检出没有。**一条在两个环境里给不同答案的检查是噪声，不是信号** —— 而它的失败模式
   尤其糟：它会训练读者忽略这条红。

2. **`.gitignore` 本来就是回答这个问题的。** 它写的是"这些东西不属于这个仓库"，地图问的是
   "这个仓库里有什么"。用忽略文件回答，是把已有的事实接上，不是新约定。

3. **残留的分歧是正确行为。** 唯一还会让两边不同的情况，是一个未被忽略的游离文件没被提交。
   那种文件**确实属于仓库**、确实应该被提交，所以那条红是对的 —— 而且现在它有一条可执行的
   指引（git 已经知道它，`git add` 即可），不是"重新生成一下"。

## 被否掉的方案

- **保持文件系统遍历，撤掉 freshness 检查。** 最简单，代价是地图过期时不再有任何信号，
  而它会被当作事实读取。
- **仅已跟踪，并把两处调用点改成"提交后再生成"。** 完全确定，但给操作员加了一个会被跳过的
  手工步骤，且 bootstrap 出来的地图在提交前一直是空的。
- **只对 `.gitignore` 里已有的目录做硬编码 SKIP。** 把每个仓库的忽略规则抄进模板，
  每加一个目录就要改一次模板 —— 与"由仓库自己定义"正好相反。

## 后果

- **地图内容会变，所以四个消费仓库都需要一次重生成** —— 这由 `1.6.3 -> 1.6.4` 步骤完成，
  与既有的"生成器变了就重生成地图"同一条规则。
- **生成器需要 `git`。** 不可用时 `trackedPaths()` 返回 `null`，各调用点回退到文件系统遍历，
  即旧行为。这条回退有测试覆盖（自检里的 fixture 就是一个真 git 仓库）。
- **地图头部改为写明这个定义**，因为读它的人需要知道边界在哪 —— 原先那段"它来自文件系统"
  的说明已随本次改动删除。

## 验证

`repo-map.mjs --self-check` 新增一组 fixture：一个真 git 仓库，含一个已跟踪文件、一个被忽略
目录、一个未跟踪未忽略文件，断言前两者不在生成的地图里、后者在。断言走**完整管线**（以
fixture 为工作目录重新执行生成器并读它的输出），不是直接调 `walk` —— 文件集对而 `render`
不传它的版本，会通过单元级断言并发布一张用旧方式生成的地图。

三个负向对照，每个都必须变红并且实测变红：

| 注入 | 结果 |
| --- | --- |
| `walk` 不按文件集过滤 | rc=1 |
| `render` 不传文件集 | rc=1 |
| 集合含被忽略文件（去掉 `--exclude-standard`） | rc=1 |

本机与真实 clone 的一致性：四个仓库逐一 `git clone` 到临时目录、用同一生成器出图、与本机
出图逐字节比对，health-flow / genesis-evidence / Auto-Test 一致；AI-Ops 的差异**恰好**是
三个未跟踪未忽略的 `docs/*.csv|docx`，符合上面"残留分歧是正确行为"。
